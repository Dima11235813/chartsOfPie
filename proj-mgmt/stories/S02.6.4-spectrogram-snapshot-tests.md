# S02.6.4 — Spectrogram snapshot regression tests

**As a** maintainer **I want** CI to fail when any preset's sound changes unexpectedly **so that**
audio changes are always deliberate and reviewed.

## Acceptance criteria

- [x] `audio-lab.html` (built with the app) exposes deterministic offline renders: fixed digits and
      seed, `Math.random` seeded during renders (Tone's reverb noise), and a warm-up render (Tone's
      first reverb in a page differs, B-015)
- [x] `e2e/audio-snapshots.spec.ts` renders every preset for 8 s and compares its spectrogram with
      the baseline in `e2e/__snapshots__/audio-snapshots.spec.ts/`. It also asserts no clipping and
      loudness of -14 ± 2 dB.
- [x] Sensitivity verified:
  - fresh-browser noise is ≤ 49 of 128,000 pixels, each by ≤ 1 level
  - a +15% reverb change on one preset fails that preset only
  - reverting passes
- [x] Baselines update with `npm run test:e2e -- audio-snapshots --update-snapshots` (documented
      in CLAUDE.md)
