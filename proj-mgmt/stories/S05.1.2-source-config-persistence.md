# S05.1.2 — SourceConfig in share links and saved pieces

**As a** listener **I want** links and saved pieces to remember which number they play **so
that** a φ or primes piece never reopens as π, on this or an older version of the app.

## Acceptance criteria

- [ ] Given any link or piece made before this story, when it opens, then it plays π exactly as
      before (all fixtures in `core/piece/fixtures/` unchanged and passing)
- [ ] Given the π source, when a share link is built, then it has no `s=` (links stay identical)
- [ ] Given a link with `s=` naming an unknown series or reading, or a newer `SourceConfig`
      version, when it opens, then the app shows the "made by a newer version" message and does
      not play π instead
- [ ] Given a piece with an unknown `source`, when read, then `readPiece` returns `too-new` and
      the store never overwrites it

## Tasks

- [ ] T1 — `core/series/sourceConfig.ts`: zod schema v1 (`series`, `reading`, `params.modulus`
      default 10), migrations chain, encode/decode, `MAX_ENCODED_SOURCE_LENGTH`
- [ ] T2 — `shareLink.ts`: parse and build `s=`; treat unknown as too-new
- [ ] T3 — `piece.ts`: additive `source` field with the π default; new golden fixture
      `fixtures/pieces/v1/with-source.json`; forward fixture with an unknown series; schema
      snapshots updated together with the default
- [ ] T4 — Share-link fixtures gain `s=` cases
- [ ] T5 — Note in R-007 that the contract now covers `s=`; redeploy the API after merge
