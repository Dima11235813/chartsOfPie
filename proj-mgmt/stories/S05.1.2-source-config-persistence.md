# S05.1.2 — SourceConfig in share links and saved pieces

**As a** listener **I want** links and saved pieces to remember which number they play **so
that** a φ or primes piece never reopens as π without a word, on this or a later version.

## Acceptance criteria

- [x] Given any link or piece made before this story, when it opens, then it plays π exactly as
      before (all fixtures in `core/piece/fixtures/` unchanged and passing)
- [x] Given the π source, when a share link is built, then it has no `s=` (links stay identical)
- [x] Given a link with `s=` naming an unknown series or reading, when it opens, then the app
      says it plays a number this version does not know, plays π meanwhile, and keeps the `s=`
      value in the link and the last session
- [x] Given a piece with an unknown `source` or a newer `SourceConfig` version, when read, then
      `readPiece` returns `too-new` (so the store and the API never overwrite it)

## Tasks

- [x] T1 — `core/series/sourceConfig.ts`: zod schema v1 (`series`, `reading`), migration chain,
      `readSourceConfig` (unknown ids are too-new), readable link values `s=<series>[.<reading>]`
- [x] T2 — `shareLink.ts`: parse and build `s=`; `newerSource` keeps an unknown value
- [x] T3 — `piece.ts`: additive `source` field with the π default; golden fixture
      `pieces/v1/with-source.json`; forward fixtures `unknown-series.json`, `source-v99.json`;
      snapshots `piece.v1.json` (changed with the default) and new `source-config.v1.json`
- [x] T4 — Share-link unit tests for `s=` (π left out, malformed, newer, round-trip); App test
      for a link from a newer app
- [ ] T5 — Redeploy the API after merge (owner; it validates with `readPiece`)
