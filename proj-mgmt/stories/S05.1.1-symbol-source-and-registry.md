# S05.1.1 — SymbolSource and series registry (π only)

**As a** developer **I want** the engine to consume a `SymbolSource` from a series registry **so
that** adding φ, Fibonacci or primes later is a data or generator change, not a pipeline change.

## Acceptance criteria

- [x] Given the app on π, when anything plays, then sound, counts, views, posters and MIDI are
      byte-identical to before (audio and poster snapshots unchanged; full e2e green)
- [x] Given `core/series/`, when tests run, then the registry holds exactly `pi` with reading
      `digits`, alphabet 10, and `core/` imports no DOM/React/Tone/Chart code
- [x] Given a source with `alphabetSize` 10, when the counter records a symbol outside 0..9,
      then it throws as today

## Tasks

- [x] T1 — `core/series/series.ts`: series and reading definitions, persisted ids (R-011 §4)
- [x] T2 — `DigitSource` gains optional `alphabetSize` (absent = 10); `SymbolSource` alias;
      `windowFrom` keeps the alphabet. `digitAt` keeps its name (R-011 §4: renaming is cosmetic
      and would churn files other threads edit)
- [x] T3 — `DigitCounter` takes an alphabet size (default 10); the engine counts with the source's
      alphabet, also after `setSource`
- [x] T4 — Registry with π; `core/series/load.ts` keeps loaders apart from metadata (the API
      imports the metadata); persisted ids pinned in `series.test.ts`
- [x] T5 — `core/README.md` updated
