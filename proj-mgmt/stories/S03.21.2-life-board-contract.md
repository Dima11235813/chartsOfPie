# S03.21.2 — LifeBoard contract, seed policies and a generic Life view

**As a** builder of views **I want** to hand Life a board (cells, neighbours, seed, where to draw)
**so that** adding Life to a view is a few lines, and it plays in place on the view's geometry.

## Acceptance criteria

- [ ] `LifeBoard` (R-013) and shared seed policies `linked`, `runs`, `threshold`, `visited`,
      `digitSet`, `shape`, each unit-tested on a small hand-made grid.
- [ ] A generic `LifeView` draws any board at the view's own cell positions (one path per colour,
      frame-budgeted) with Run/Pause Life, Next, Speed, Restart and back.
- [ ] View definitions gain an optional `lifeBoard(state)`; the stage offers **Game of Life**
      when it returns a board (one tap pauses the digits and launches).
- [ ] The mosaic uses all of this with no visible change: the existing e2e cases (launch, step,
      filters, back, one tap while playing, phone layout) pass unchanged.

## Tasks

- [ ] T1 — `viz/life/board.ts` (types) and `viz/life/seeds.ts` (policies) with tests
- [ ] T2 — `viz/render/lifeRenderer.ts` and a generic `LifeView`
- [ ] T3 — Registry hook; mosaic board built from its renderer's `grid()`
- [ ] T4 — Remove the mosaic-only paths once the generic ones pass
