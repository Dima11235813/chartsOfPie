# S01.7.2 — More than a million digits

**As a** listener **I want** π beyond the first million digits **so that** there is always more
to explore.

## Today

The app already reads its limits from the data (`DigitSource.length`): a longer `pi-1m.txt`
would just work up to a few million digits. Beyond that, one text file costs one byte per digit to
download and keep in memory, and search builds one string of the whole thing.

## Approach (to refine)

- Packed chunks: 2 digits per byte, e.g. 1M digits per chunk, with a manifest (digit count, sha256
  per chunk) so the data stays verifiable (F01.2)
- A `DigitSource` that fetches chunks on demand around the current position and prefetches ahead;
  `windowFrom` and every view already work on any source
- Search chunk by chunk (with overlap) in a Web Worker, cancellable
- Cache chunks offline with the PWA (F10.5)

## Acceptance criteria

- [ ] 10M+ digits playable from any position with no long tasks (`npm run perf`)
- [ ] Data verified per chunk; a corrupted chunk fails loudly
