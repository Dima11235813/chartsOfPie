# F10.1 — Versioned piece schema & compatibility contract

## Why

Saved pieces and share links outlive app versions. Every version of the app must read every
document any earlier version wrote, and must never damage one a newer version wrote.

## Stories

- [x] S10.1.1 — `Piece` document (zod): envelope + `sound` (CompositionConfig) + `visual`
      (VisualConfig) + optional position; `parsePiece` returns ok / needs-migration / too-new / invalid
- [x] S10.1.2 — Ordered migration pipeline (`vN → vN+1`, pure, chained) for the piece, the sound
      config and the visual config; unknown keys round-trip
- [x] S10.1.3 — Golden fixtures `fixtures/pieces/v1/*.json` and `fixtures/share-links/*.txt`,
      validated in CI forever (deleting one fails a test)
- [x] S10.1.4 — Schema snapshot guard: `toJSONSchema()` output committed; a shape change fails
      CI until it is additive-with-defaults or versioned with a migration and fixtures
- [x] S10.1.5 — Document the contract in CLAUDE.md (rule 8) and the `proj-mgmt` skill

## Delivered

- `core/schema/migrate.ts` (pipeline, `preserveUnknown`), `core/piece/{piece,visualConfig,shareLink}.ts`.
- Fixtures: `core/piece/fixtures/pieces/v1/*` (golden, manifest-checked), `fixtures/forward/*`
  (documents from newer apps), `fixtures/share-links.json` (links in the wild).
- Snapshots: `core/piece/__schemas__/*.json` via `toJSONSchema({ io: 'input' })`; excluded from
  Prettier so the bytes are exact. Verified: adding a field fails 4 tests; a missing snapshot fails
  under `CI=true`.
- Unknown values (e.g. a view from a newer app) read as defaults and flag `replaced`, so the
  store (F10.3) can open them read-only instead of overwriting.

## Acceptance

- Every fixture of every version parses into the current shape.
- A document with an unknown future version is reported "too new", never rewritten.
- Changing a schema field without a migration or snapshot update fails `npm run check`.
