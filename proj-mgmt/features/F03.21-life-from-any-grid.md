# F03.21 — Game of Life from any view

## Why

Owner (2026-10-31): "extend this to use any grid that could feed patterns into Life … plan it for
every single visualization we do going forward." The mosaic's Game of Life (F03.4, PR #38) is the
first case. [R-013](../research/R-013-life-from-any-grid.md) has the abstraction (`LifeBoard`:
topology, rule, seed, cell positions, optional notes), the per-view table and the cost figures.

## Stories

Foundation, in order:

- [ ] [S03.21.1](../stories/S03.21.1-life-engine-topologies.md) — Engine: square (fast path,
      wrap or not), graph and line topologies; Life-like B/S rules and elementary rules 30/90/110;
      colour rule and settling shared; mosaic results unchanged (M)
- [ ] [S03.21.2](../stories/S03.21.2-life-board-contract.md) — `LifeBoard` contract, shared seed
      policies (`linked`, `runs`, `threshold`, `visited`, `digitSet`, `shape`), generic board
      renderer and `LifeView`, registry hook `lifeBoard()`; the mosaic moved onto it with no
      visible change (M)
- [ ] S03.21.3 — Raster fallback: any view's canvas sampled into a grid (ink = alive, nearest
      palette colour), so every view has **Game of Life**; one stage-level action and key `L` for
      views without a bar; rule-9 e2e for every view (M)
- [ ] S03.21.4 — Big boards in a Web Worker (> 64k cells), measured with `npm run perf`
      (`CPU=4`: no rhythm stumbles while Life runs) (M)

Views, by priority (R-013 table):

- [ ] S03.21.5 — Guitar fretboard: strings × frets, seed = positions played recently, no wrap (S)
- [ ] S03.21.6 — Sheet music: pitch × time piano roll, seed = notes in the visible bars (M)
- [ ] S03.21.7 — Golden rectangle: its Fₖ × Fₖ₊₁ cells, linked seed, spiral kept on top (S)
- [ ] S03.21.8 — Typographic π: text grid, seed = glowing runs (S)
- [ ] S03.21.9 — Sound for births: `noteOf(cell)` per board, played through the current preset,
      rate-limited; silent by default, a toggle (owner choice "silent first", R-013) (M)
- [ ] S03.21.10 — Hilbert carpet: 1024² in the worker, zoomed window like the live view (M)
- [ ] S03.21.11 — Digit ring: the k × k transition table as a board (S)
- [ ] S03.21.12 — Sunflower: graph topology over the Fibonacci neighbours, hex-like rule B2/S34 (M)
- [ ] S03.21.13 — π walk, cymatics, spectrogram: binned boards (visited cells, sand, energy) (M)
- [ ] S03.21.14 — Digit chart / stream: 1-D elementary automata (rules 30, 90, 110) from digit
      parity, drawn as rows over time (M)
- [ ] S03.21.15 — String art and music clock: ring (line) boards (S)
- [ ] S03.21.16 — Persisted Life settings (`viewOptions.life`: rule, wrap, speed; additive with
      defaults, rule 8) (S)
- [ ] S03.21.17 — Lessons (E04): gliders, square vs hexagon, rule 30 (M)

## Standing rule (every visualization from now on)

A new view ships with its **Life board**, or a line in its feature file saying why the raster
fallback is enough, plus a rule-9 e2e case that launches Life from it while paused and goes back
(CLAUDE.md rule 10, `add-visualization` skill step 5, the feature template's "Life board"
section).

## Notes

Owner choices from F03.4 carry over: seeds respect what the view is showing (filters), cells keep
their digit colours, wrap-around edges where the view has no natural edge, silent until S03.21.9.
